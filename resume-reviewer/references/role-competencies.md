# Role Competency Map

Use these categories to ask better questions and select evidence. Treat keywords as prompts, not claims.

## Frontend Engineering

- **Competencies:** component reuse, state management, accessibility, responsive UI, browser behavior, performance, testing, design-system integration.
- **Evidence prompts:** Which components became reusable? Which user flow changed? Which rendering, bundle, accessibility, or test issue was addressed?
- **Useful proof:** Core Web Vitals, bundle size, render time, accessibility checks, test coverage, supported breakpoints, component count, user adoption.
- **Common terms:** React, TypeScript, JavaScript, CSS, state management, accessibility, responsive design, unit testing, end-to-end testing.

## Backend Engineering

- **Competencies:** API contracts, data modeling, concurrency, scalability, reliability, security, caching, observability, testing.
- **Evidence prompts:** Which endpoint, service, or schema changed? What load or failure mode existed? Which tradeoff affected consistency, latency, or maintainability?
- **Useful proof:** request volume, p95 latency, throughput, error rate, endpoint count, query time, cache hit rate, test coverage, uptime.
- **Common terms:** REST, GraphQL, SQL, NoSQL, authentication, authorization, caching, message queues, microservices, integration testing.

## Full-Stack Engineering

- **Competencies:** end-to-end feature delivery, client-server contracts, authentication, data flow, deployment, observability, test strategy.
- **Evidence prompts:** Which user workflow crossed frontend and backend? Which interface or deployment constraint required coordination?
- **Useful proof:** completed workflows, API/UI integration count, deployment frequency, response time, test layers, users or teams supported.

## AI and Machine Learning Engineering

- **Competencies:** data pipelines, training and evaluation, model serving, inference optimization, monitoring, reproducibility, safety, retrieval.
- **Evidence prompts:** Which dataset, model, baseline, evaluation metric, serving path, or latency target existed? What changed between experiment and deployment?
- **Useful proof:** dataset size, precision, recall, F1, accuracy, latency, throughput, memory use, cost, drift checks, experiment count.
- **Common terms:** PyTorch, TensorFlow, scikit-learn, embeddings, retrieval-augmented generation, model serving, feature engineering, evaluation, MLOps.

## Data Engineering and Analytics

- **Competencies:** ingestion, transformation, orchestration, data quality, warehouse modeling, lineage, analytics, reporting.
- **Evidence prompts:** Which source, schema, refresh frequency, consumer, or quality rule mattered? How was failure detected or recovered?
- **Useful proof:** rows, sources, pipeline runtime, freshness, failure rate, query time, dashboard use, data-quality checks.

## Cloud, DevOps, and SRE

- **Competencies:** infrastructure as code, CI/CD, containers, reliability, observability, incident response, cost, security controls.
- **Evidence prompts:** Which deployment or operational bottleneck changed? Which service-level target, rollback, alert, or automation was implemented?
- **Useful proof:** build time, deployment frequency, recovery time, uptime, alert noise, cost, environment count, manual steps removed.

## Mobile Engineering

- **Competencies:** platform APIs, lifecycle, offline behavior, networking, performance, accessibility, testing, release workflows.
- **Evidence prompts:** Which device, OS, lifecycle, synchronization, or store-release constraint existed?
- **Useful proof:** supported versions, crash rate, startup time, screens, devices, test coverage, release status.

## Product Management

- **Competencies:** user requirements, prioritization, product discovery, success metrics, documentation, experimentation, stakeholder alignment, lifecycle execution.
- **Evidence prompts:** Which user problem, decision, tradeoff, requirement, or launch outcome belonged to candidate? Which engineering or design partners were involved?
- **Useful proof:** users interviewed, requirements accepted, experiment result, adoption, delivery milestone, backlog scope, stakeholder groups.
- **Note:** `PM` means Product Manager only when user confirms it.

## Project or Program Management

- **Competencies:** scope, schedule, dependency tracking, risk, documentation, delivery coordination, status communication, retrospective improvement.
- **Evidence prompts:** Which milestones, dependencies, blockers, or handoffs were coordinated? Which deliverable reached acceptance?
- **Useful proof:** milestone count, teams, duration, risks closed, delivery variance, cycle time, stakeholder groups.
- **Note:** Do not merge this profile with Product Management.

## Transferable Early-Career Evidence

Retain nontechnical work only when it proves target-relevant behavior such as troubleshooting, customer discovery, operational accuracy, documentation, training, prioritization, or cross-functional delivery. Translate facts without changing official title or implying technical work that did not occur.
